\begin{abstract}
The Agentic Audit \& Reliability Contract (AARC) v1.0.5 specifies a machine-verifiable
telemetry format (the AARC State Vector), a non-self-approving validation protocol
(Actor--Critic--Judge), and a runtime enforcement boundary (Monitor + capability-gated Tool Gateway).
Together, these artifacts provide auditability, traceability, and hard guardrails
against role/objective drift. This paper summarizes the v1.0.5 release and its
interoperability and security requirements.
\end{abstract}

\section{Introduction}
Agentic systems fail in predictable ways: missing or non-comparable logs, silent
goal drift, tool calls that are not policy-scoped, and ``self-approval'' loops
where the same actor effectively validates its own output.
AARC addresses these failure modes with a small set of versioned, portable
artifacts designed for implementation in Python or TypeScript runtimes.

AARC v1.0.5 is shipped as a specification repository and a reproducible build.
The compiled PDF embeds a deterministic hash of the v1.0.5 specifications so any
spec edits are detectable in the document build output. Spec hash:
\texttt{\specHash}.

an \emph{AARC State Vector} entry that can be validated by a Judge, Monitor, or

\section{AARC State Vector (Audit Log Primitive)}
The State Vector is the primary machine-readable log entry for AARC. Implementations
must emit State Vectors that validate against the v1.0.5 schema.
At minimum, a State Vector binds:
\begin{itemize}
  \item \textbf{Identity anchors}: agent id, root agent, parent id, role token.
  \item \textbf{Intent anchors}: immutable objective/policy hashes and root anchors.
  \item \textbf{Traceability}: run id, step id, sequence number, and continuity metadata.
  \item \textbf{Inputs/assumptions}: digests and declared assumptions used for reasoning.
  \item \textbf{Governed metrics}: confidence/uncertainty/evidence coverage used at decision time.
  \item \textbf{Side-effects}: tool events (or capability usage) when in TM-B deployments.
\end{itemize}

The design goal is simple: a verifier can read a sequence of State Vectors and
determine whether invariants were upheld without depending on an agent’s internal
reasoning trace.

\section{Actor--Critic--Judge (ACJ) Protocol (Non-Self-Approval)}
AARC uses an Actor--Critic--Judge protocol to prevent self-approval.
\begin{itemize}
  \item The \textbf{Actor} generates a proposal and must not finalize approval.
  \item The \textbf{Critic} evaluates the proposal using required attack vectors
        (e.g., evidence gaps, contradiction, boundary violation, hallucination risk).
  \item The \textbf{Judge} issues the only valid approval decision and records governed metrics.
\end{itemize}

In AARC-compliant systems, a proposal becomes ``approved'' only if the Judge (and,
where configured, receipt verification) confirms that the Critic evaluation and
decision chain are present and consistent with the run’s immutable anchors.

\section{Runtime Contract and Enforcement Boundary}
AARC is designed around an enforcement boundary:
\begin{itemize}
  \item A \textbf{Monitor} is authoritative for commit order, invariant checks,
        override envelope enforcement, and kill-switch execution.
  \item In TM-B deployments, a \textbf{Tool Gateway} mediates all tool calls via
        capability tokens and logs TOOL\_EVENT entries as State Vectors.
\end{itemize}

This separation is essential: policy-scoped side effects are enforced outside the
agent’s own text generation loop. If identity or intent invariants are violated
mid-run, the Monitor revokes capabilities and terminates the run.

\section{Patch Ledger (Evolution Record)}
The patch ledger is an append-only record of protocol fixes and release closures.
Each patch entry is intended to be linkable to motivating evidence (telemetry
and/or validation findings) and supports operational governance:
auditors can answer ``what changed'' and ``why'' across versions.

\section{Formal Invariants and Properties}
AARC v1.0.5 requires the following invariants and properties across implementations:
\begin{itemize}
  \item \textbf{I1 (Identity Invariance)}: role/identity anchors must not change
        after GENESIS. \textit{Enforced by}: Monitor checks at commit and tool boundaries.
  \item \textbf{I2 (Intent Invariance)}: objective/policy anchors (and root hashes)
        must remain immutable for the run. \textit{Enforced by}: Monitor hash checks and kill-switch.
  \item \textbf{P1 (State Vector Completeness)}: lifecycle steps emit schema-valid
        State Vectors with traceability and inputs/assumptions. \textit{Enforced by}:
        schema validation and runtime contract.
  \item \textbf{P2 (Non-Self-Approval)}: Actor cannot unilaterally approve; approval
        requires Critic evaluation and Judge decision. \textit{Enforced by}: ACJ protocol and
        receipt verification (where configured).
  \item \textbf{P3 (Policy-Scoped Side Effects)}: tool calls must be policy-scoped and,
        in TM-B, capability-gated. \textit{Enforced by}: Tool Gateway + Monitor revocation.
  \item \textbf{P4 (Conformance Gate)}: releases are valid only when schema checks,
        paper build, and arXiv bundle packaging succeed. \textit{Enforced by}:
        CI conformance checks and release scripts.
\end{itemize}

\section{Conformance Test Plan}
An implementation is AARC-compliant when the following checks pass:
\begin{enumerate}
  \item \textbf{Schema validation}: emitted State Vectors validate against the v1.0.5 schema.
  \item \textbf{Anchor immutability}: root objective/policy/identity anchors remain constant
        after GENESIS; violations trigger kill-switch.
  \item \textbf{ACJ validity}: proposals are evaluated by Critic and finalized only by Judge;
        Actor cannot approve.
  \item \textbf{Policy-scoped tooling}: tool usage is logged and policy-scoped; in TM-B, calls
        require valid capability tokens.
  \item \textbf{Release checks}: schema sanity, paper build, and arXiv packaging succeed.
\end{enumerate}

\section{Ablation Analysis}
Removing AARC components produces predictable reliability regressions:
\begin{itemize}
  \item \textbf{Without the Monitor}: anchor immutability and kill-switch enforcement degrade,
        increasing drift and tool misuse risk.
  \item \textbf{Without ACJ}: proposals can self-validate, increasing false approvals and
        reducing audit confidence.
  \item \textbf{Without the Tool Gateway (TM-B)}: tool calls become harder to constrain and
        attribute, weakening policy-scoped side-effect guarantees.
\end{itemize}

\section{Conclusion}
AARC v1.0.5 provides a concise, interoperable foundation for auditable agentic systems:
machine-verifiable State Vectors, a non-self-approving validation protocol, and a hard
enforcement boundary for identity/intent invariance and policy-scoped side effects.
Future work will expand adapters and conformance tooling while preserving the minimal
core protocol.
